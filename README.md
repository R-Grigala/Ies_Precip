# Ies_Precip

Flask-ზე აგებული ნალექის მონიტორინგის სისტემა. პროექტი აერთიანებს ამინდის სადგურებიდან მიმდინარე მონაცემების წამოღებას, მონაცემთა ბაზაში ისტორიის შენახვას, რუკაზე ჩვენებას, მონაცემების გაფილტვრასა და CSV-დ ექსპორტს. ადმინისტრატორს შეუძლია სადგურებისა და მომხმარებლების მართვა.

## პროექტის ნაწილები

- **ვებაპი** — Flask-ის აპლიკაცია, HTML/Jinja შაბლონები და JavaScript.
- **REST API** — Flask-RESTX-ზე აგებული, `/api`-ზე განთავსებული ბოლო წერტილები. Swagger UI ხელმისაწვდომია `/api` მისამართზე.
- **მონაცემთა ბაზა** — SQLAlchemy მოდელები და Flask-Migrate/Alembic მიგრაციები. მიმდინარე ნაგულისხმევი კონფიგურაცია MySQL-ს ელოდება.
- **განრიგი** — ცალკე Python პროცესი, რომელიც გარე სადგურებს კითხულობს და მონაცემებს პერიოდულად ინახავს.
- **განთავსება** — Docker Compose, Flask/uWSGI, Nginx და MySQL.

## ძირითადი შესაძლებლობები

1. რუკაზე სადგურების ადგილმდებარეობისა და ნალექის მიმდინარე მაჩვენებლების ჩვენება.
2. კონკრეტული სადგურის მონაცემების თარიღით, დროითა და ინტერვალით გაფილტვრა.
3. რამდენიმე სადგურის მონაცემების CSV ფაილად ჩამოტვირთვა.
4. JWT-ით შესვლა, მომხმარებლებისა და როლების მართვა, პაროლის ელფოსტით აღდგენა.
5. ადმინისტრატორის მიერ სადგურის დამატება, რედაქტირება და წაშლა.

## როგორ მუშაობს მონაცემთა ნაკადი

`tools/scheduler.py` პერიოდულად იძახებს ამოცანებს `tools/` ქვეპროექტიდან. `update_temporary_db.py` Weather.com-ის PWS API-ს უკავშირდება და `div_positions`-ში მიმდინარე მნიშვნელობებს ანახლებს. `insert_precip_long_db.py` ითვლის გრძელვადიან დაგროვებას `prev_precip`-ის მდგომარეობის გამოყენებით. `insert_precip_db.py` მიმდინარე მნიშვნელობებს `weather_data`-ში ისტორიულ ჩანაწერებად ამატებს. რუკა ამ მონაცემებს API-დან იღებს, ფილტრისა და ექსპორტის API კი ისტორიულ ცხრილს კითხულობს.

## სწრაფი დაწყება ლოკალურად

საჭიროა Python 3, MySQL და `.env` ფაილში სწორად გაწერილი პარამეტრები.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

შექმენი `.env` ფაილი (ფაილში რეალური საიდუმლო მნიშვნელობები არ შეინახო ვერსიების კონტროლში):

```dotenv
MY_SECRET_KEY=replace-with-a-long-random-value
JWT_SECRET_KEY=replace-with-another-long-random-value
MYSQL_HOST=127.0.0.1
MYSQL_DATABASE=ies_precip
MYSQL_USER=ies_precip_user
MYSQL_PASSWORD=replace-me
MAIL_SERVER=smtp.example.org
MAIL_PORT=587
MAIL_USERNAME=app@example.org
MAIL_PASSWORD=replace-me
```

აპის გაშვება:

```bash
python app.py
```

ლოკალურად გვერდი იქნება `http://127.0.0.1:5000/`, ხოლო API დოკუმენტაცია — `http://127.0.0.1:5000/api`.

მონაცემთა ბაზის ცხრილების მართვისთვის გამოიყენე Flask-Migrate (`flask db upgrade`). CSV-დან საწყისი მონაცემების ჩასატვირთად პროექტში არის `flask populate_db`, თუმცა ეს ბრძანება შეიცავს საწყისი მომხმარებლების კოდში გაწერილ მონაცემებს და გამოყენებამდე უნდა გადაიხედოს. `flask init_db` ასრულებს `drop_all()`-ს და **შლის არსებულ ცხრილებსა და მონაცემებს**.

## Docker

Docker Compose-ის კონფიგურაცია მოითხოვს იმავე გარემოს ცვლადებს `.env`-ში:

```bash
docker compose up --build
```

Compose-ში გაშვებულია Flask/uWSGI, Nginx და MySQL. Nginx HTTP მოთხოვნებს host-ის `2024` პორტზე იღებს; MySQL host-ზე `3307` პორტით ჩანს. კონტეინერის პირველ გაშვებაზე ბაზის მიგრაციები და seed მონაცემები ავტომატურად არ იტვირთება.

## გასათვალისწინებელი

- [src/config.py](src/config.py)-ში MySQL არის აქტიური ნაგულისხმევი კონფიგურაცია; SQLite URI მხოლოდ კომენტარადაა დარჩენილი.
- ლოკალური `python app.py` გაშვება `debug=True`-ს იყენებს. ეს რეჟიმი წარმოებაში არ გამოიყენო.
- `populate_db`-ში საწყისი ანგარიშები კოდშია გაწერილი. ისინი უნდა შეიცვალოს ან seed მექანიზმი უნდა მოერგოს გარემოს.
- სადგურის API მისამართის აგებისას კოდში Weather.com API key არის მითითებული. გასაღები უნდა იმართებოდეს გარემოს კონფიგურაციით და საჭიროების შემთხვევაში განახლდეს.
- scheduler Compose-ში ცალკე სერვისად განსაზღვრული არ არის: Flask კონტეინერის ბრძანება მას ფონურ პროცესად უშვებს. ეს განლაგებისას გასათვალისწინებელია.
