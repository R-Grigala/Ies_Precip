# REST API ცნობარი

ყველა API რესურსის ბაზური პრეფიქსია `/api`. Swagger UI: `/api`.

JWT-ით დაცულ მოთხოვნებს გაუგზავნე header:

```http
Authorization: Bearer <access_token>
```

კონკრეტული ველები და ვალიდაცია განსაზღვრულია `src/api/nsmodels/`-ში. ქვემოთ მოცემულია კოდში რეგისტრირებული ძირითადი რესურსები.

## ავტორიზაცია

| მეთოდი და გზა | JWT | დანიშნულება |
| --- | --- | --- |
| `POST /api/login` | არა | ელფოსტითა და პაროლით შესვლა; აბრუნებს access და refresh token-ს. |
| `POST /api/refresh` | Refresh token | ახალი access token-ის მიღება. |
| `POST /api/registration` | Access token + admin | ახალი ანგარიშის შექმნა; პაროლი მინიმუმ 8 სიმბოლოა და გამეორებას უნდა ემთხვეოდეს. |

შესვლის მოთხოვნა იღებს `email` და `password` ველებს; რეგისტრაცია დამატებით იღებს `passwordRepeat` და `role_name` ველებს.

## მომხმარებლის ანგარიშები და პაროლი

| მეთოდი და გზა | JWT | დანიშნულება |
| --- | --- | --- |
| `GET /api/user` | დიახ | მიმდინარე მომხმარებლის მონაცემები. |
| `GET /api/users` | Admin | ყველა მომხმარებლის სია. |
| `PUT /api/user/<uuid>` | Admin | მომხმარებლის ელფოსტისა და როლის შეცვლა. |
| `DELETE /api/user/<uuid>` | Admin | მომხმარებლის წაშლა. |
| `POST /api/request_reset_password` | არა | ელფოსტით პაროლის შეცვლის ბმულის მოთხოვნა; ხელახალი გაგზავნა შეზღუდულია 60 წამით. |
| `PUT /api/reset_password` | Reset token body-ში | პაროლის შეცვლა; token-ის მოქმედების მაქსიმალური დრო 300 წამია. |

## სადგურები

| მეთოდი და გზა | JWT | დანიშნულება |
| --- | --- | --- |
| `GET /api/stations` | დიახ | ყველა სადგურის მეტამონაცემები. |
| `POST /api/stations` | Admin | სადგურის შექმნა; ქმნის ასევე `DivPositions` და `PrevPrecip` ჩანაწერებს. |
| `GET /api/stations/<id>` | დიახ | ერთი სადგურის დეტალები. |
| `PUT /api/stations/<id>` | Admin | სადგურისა და რუკის ჯგუფის განახლება. |
| `DELETE /api/stations/<id>` | Admin | სადგურის წაშლა; თუ `weather_data` ჩანაწერი არსებობს, მოთხოვნა უარყოფილია. |

სადგურის შექმნისა და რედაქტირების მოთხოვნები იღებს ველებს: `station_name`, `url`, `latitude`, `longitude`, `map_selected`, `map_status`, `fetch_status`. URL-ის ბოლო ნაწილი გამოიყენება API-ში სადგურის ID-ად.

## რუკა, ფილტრაცია, ექსპორტი

| მეთოდი და გზა | JWT | დანიშნულება |
| --- | --- | --- |
| `GET /api/stations/div_positions` | არა | რუკის განლაგება და მიმდინარე მაჩვენებლები. |
| `POST /api/filter` | დიახ | ერთი სადგურის ისტორიული მონაცემების ფილტრაცია. |
| `POST /api/export` | დიახ | რამდენიმე სადგურის მონაცემების CSV ფაილად ექსპორტი. |

`/filter` მოითხოვს `station_id`, `date` (`YYYY-MM-DD`), `start_time`, `end_time` (`HH:MM:SS`) და `step_min`. `/export`-ს ასევე სჭირდება `start_date`, `end_date`, `station_ids` (განმეორებადი ველი) და დროის საზღვრები. `step_min` უნდა იყოფოდეს 5-ზე. კოდი მონაცემს ყოველ 5 წუთში ერთხელ არსებულ რიგში ამუშავებს; ეს რეალური დროის ჭრილს არ აჯამებს და ჩანაწერების თანაბარ ინტერვალს ვარაუდობს.

## შეცდომები და ქცევის შენიშვნები

- API პასუხები იყენებს ჩვეულებრივ HTTP სტატუსებს: 400 არასწორი არგუმენტი, 401/403 ავტორიზაციის ან უფლების პრობლემა, 404 მონაცემის არქონა.
- `/filter`-ის შეკითხვა შედეგებს `precip_time`-ით ცალსახად არ ალაგებს; შესაბამისად, step-ით შერჩევის რიგი გარანტირებული არ არის.
- `/export` ფაილს `export/` დირექტორიაში წერს და response attachment-ად აბრუნებს; ფაილის სახელად მხოლოდ თარიღებია გამოყენებული.
- JWT Swagger-ის სქემაში API key header-ადაა აღწერილი. რეალური JWT header-ის ფორმა Flask-JWT-Extended-ის მოთხოვნის წესს უნდა შეესაბამებოდეს.
